════════════════════════════════════════════════════════
COMUNE (Add-on + Standalone)
════════════════════════════════════════════════════════

- OCR opt-in: casella «Includi testo in immagini e PDF scansionati» (spento di default).
- Scelta motore OCR:
  • Windows.Media.Ocr (predefinito, già incluso nel sistema)
  • EasyOCR (opzionale, se installato) — migliore su scritte stilizzate
- Menu / elenco «Motore OCR»; preferenza e profili (include_ocr, ocr_engine).
- Risultati [IMG-OCR] e [PDF-OCR] con snippet; cache locale per motore; contatori nello stato.
- Preprocess immagini: contrasto, soglia, stripe, ritagli, rotazioni, upscale;
  scelta della migliore variante OCR (meno «zuppe» di caratteri).
- Match OCR tollerante: testo invertito, confusabili, fuzzy (es. fiBlRTHDW ≈ birthday),
  alias BIRTHDAY; sinonimi birthday↔compleanno; anti falso-positivo (es. «tribunale»).
- BIRTHDAY verticale: ritaglio destro «clean» + rotazioni; se EasyOCR non matcha → Windows.
- Menu contestuale sui risultati immagine:
  • «Copia Testo pulito» (es. HAPPY BIRTHDAY + nome)
  • «Copia OCR completo» (tutto: canzone, sponsor, testo grezzo)
- OCR senza parola chiave: OCR attivo + testo vuoto → Avvia = elenco immagini con testo.
- Evoluzione futura (non in 1.5.8): Azure/Google Vision con chiave personale dell’utente.
- Restano voce/Mute 1.5.7, posta completa 1.5.6, date, profili e filtri.

════════════════════════════════════════════════════════
PERCHÉ DUE MOTORI (tecnico)
════════════════════════════════════════════════════════

Windows.Media.Ocr
  - Già in Windows 10/11; zero pacchetti pesanti; adatto all’Add-on NVDA.
  - Veloce e leggero; su grafiche a strisce / font estremi spesso “garbla” il testo.

EasyOCR (torch)
  - Opzionale, installazione pip; modelli ~100+ MB al primo uso (poi offline).
  - Molto meglio su scritte stilizzate (compleanni Juve, loghi).
  - Pesante (CPU/RAM): pratico nella Standalone (Python dedicata), non da bundlare in NVDA.

Strategia RTAD 1.5.8
  - Stesso modulo gemello rtad_ocr.py (Standalone + Add-on).
  - Predefinito: Windows. EasyOCR selezionabile se importabile.
  - Standalone: percorso consigliato per prove EasyOCR (requirements-ocr-easy.txt).
  - Add-on: Windows come percorso principale; EasyOCR solo se già presente nell’ambiente NVDA
    (non incluso nel .nvda-addon — evita pacchetto gigante e conflitti).

════════════════════════════════════════════════════════
SOLO STANDALONE
════════════════════════════════════════════════════════

- Installazione EasyOCR (stessa Python di RTAD):
    pip install -r requirements-ocr-easy.txt
- Al primo uso EasyOCR scarica i modelli (Internet una volta; poi offline).
- Cache in %AppData%\RTAD_Standalone\ocr_cache\.
- Consigliato: Motore OCR → EasyOCR per grafiche difficili; Windows resta disponibile.

════════════════════════════════════════════════════════
SOLO ADD-ON
════════════════════════════════════════════════════════

- Windows OCR = percorso principale (zero dipendenze pesanti nel pacchetto NVDA).
- EasyOCR solo se il modulo è già importabile nell’ambiente Python di NVDA
  (non viene installato dall’Add-on; per prove EasyOCR usare la Standalone).
- Cache in rtad_data\ocr_cache\.
- Stesse funzioni OCR di ricerca/copia del gemello Standalone (codice condiviso).

- **Opt-in OCR** (off by default): text in images and scanned PDFs.

- Context menu: **Copy clean text** and **Copy full OCR**.
- OCR without a search query: enable OCR, leave the query empty, Start.
